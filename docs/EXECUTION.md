# 执行规则（EXECUTION.md）

## 文档权威顺序

1. 用户当前明确指令。
2. 根目录 `AGENTS.md`。
3. `docs/GOAL.md`。
4. `docs/EXECUTION.md`（本文件）。
5. `docs/STATE.json`（动态状态唯一真源）。
6. 当前工作包规范（`docs/work-packages/WP-XX.md`）。
7. `docs/功能开发清单.xlsx`（业务范围唯一真源）。
8. 遗留参考：`old/`。

## 执行算法

Codex 每次开始工作时只读取：

- `AGENTS.md`
- `docs/GOAL.md`
- `docs/EXECUTION.md`
- `docs/STATE.json`
- 当前工作包

执行流程：

1. 如果存在 `in_progress` 工作包，继续它。
2. 否则选择依赖全部完成的第一个 `ready` 工作包。
3. 将其改为 `in_progress`。
4. 只完成该工作包范围。
5. 执行工作包要求的测试和构建。
6. 验证通过后改为 `done`。
7. 创建包含工作包 ID 的 Git 提交。
8. 将下一个依赖已满足的工作包改为 `ready`。
9. 自动继续执行。
10. 到达阶段门禁时停止。

## 停止条件

只有以下情况停止：

- 到达人工或混合阶段门禁。
- Excel 需求存在无法判断的冲突。
- 测试经过合理修复后仍无法通过。
- 需要真实外部服务、账号或凭据。
- 工作包范围发生重大变化。
- 存在用户未提交修改且无法判断归属。

## 阶段与门禁

### S0：需求和架构确认

**任务**：

- 读取功能开发清单。
- 确认一期、二期、三期范围。
- 确定业务包。
- 确定数据库重新设计原则。
- 确定必要技术版本。
- 生成实际工作包。

**G0**：人工门禁。

需要用户确认：

- 总 Goal。
- 一期、二期范围。
- 业务包划分。
- 工作包清单。
- 关键技术选型。

G0 通过后，Codex 自动进入 S1。

### S1：工程骨架与平台基础

**任务**：

- 后端工程骨架。
- PC 工程骨架。
- uni-app 工程骨架。
- pnpm workspace。
- 数据库迁移基础。
- 身份、权限、组织、流程、文件、消息、审计基础。
- ArchUnit。
- CI 和基础测试。

**G1**：自动门禁。

要求：

- 后端构建和测试通过。
- PC 构建和测试通过。
- uni-app H5 构建通过。
- 数据库迁移测试通过。
- ArchUnit 通过。
- CI 通过。

### S2：一期功能

**任务**：

- 执行 Excel 中全部一期工作包。

每个工作包完成后自动：

- 执行测试。
- 执行构建。
- 更新状态。
- 创建包含工作包 ID 的提交。
- 继续下一个 ready 工作包。

**G2**：混合门禁。

自动条件：

- 一期工作包全部 done。
- 一期需求全部覆盖。
- 自动化测试通过。
- PC 与 H5 构建通过。

自动条件通过后停止，等待用户进行一次阶段验收。

### S3：二期功能

**任务**：

- 执行 Excel 中全部二期工作包。

**G3**：混合门禁。

- 二期工作包全部完成。
- 回归测试通过。
- 用户进行一次阶段验收。

### S4：集成与发布

**任务**：

- 全量集成测试。
- 安全检查。
- 性能基础验证。
- 安装备份恢复。
- 发布回滚。
- 用户文档。
- 运维文档。

**G4**：最终人工门禁。

## 提交规则

- 每个工作包至少一个独立提交。
- 格式：`feat(WP-XX): 描述` 或 `fix(WP-XX): 描述`。
- 提交前运行当前工作包定义的验证命令。
- 禁止使用：`1`、`add`、`update`、`done`。
- 不得修改 Git 历史。
- 不得擅自删除用户修改。

## 编码约束

- 所有代码注释使用中文。
- 所有文件写入使用 UTF-8 without BOM。
- 项目使用 `pnpm` 作为包管理工具。
- 项目依赖锁定文件统一使用 `pnpm-lock.yaml`。
- 禁止创建 `package-lock.json`、`yarn.lock`。

## 禁止项

- 禁止把 `old/` 中的代码直接复制为新实现。
- 禁止新代码依赖 `old/`。
- 禁止在文档中把旧功能声明为新系统已完成。
- 禁止在 `old/` 之外硬编码密码、密钥、数据库地址、Redis 地址和默认账号。
- 禁止在提交信息中使用 `1`、`add`、`update`、`fix`、`done`。
- 禁止推送远程。
- 禁止修改 Git 历史。
- 禁止丢弃用户未提交修改。
- 禁止使用 `npm` 或 `yarn` 执行依赖安装、删除、更新及项目脚本。
- 禁止在依赖工作包完成前将后续工作包标记为 `in_progress`。
- 禁止在自动验证未通过时进入下一阶段。
- 禁止在工作包范围扩大时继续执行而不上报。
