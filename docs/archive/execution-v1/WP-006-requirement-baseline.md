# WP-006：需求基线与阶段映射

## 目标

重新核对功能开发清单，冻结一期、二期、三期需求映射，修订需求追踪矩阵，输出可作为 G1 输入的需求基线。

## 范围

- 以功能清单“阶段”列为真源，核对每个需求的阶段归属。
- 修正 TRACEABILITY.md 中的阶段统计和错位条目。
- 确认公文交换为三期 deferred，不进入当前实施范围。
- 确认需求编号、业务域、业务包/前端功能域映射。
- 将核对结果和差异记录到 evidence。

## 不在范围

- 不修改功能开发清单.xlsx 源文件。
- 不决定最终业务包拆分。
- 不开始业务代码开发。

## 依赖

- WP-005：G0 后执行体系一致性修复（done）

## 风险

- 高：功能清单的“阶段”列与“难易度统计”页口径不一致，需要人工确认。
- 中：需求映射变更可能影响 S1 后续工作包范围。

## 验收标准

1. TRACEABILITY.md 中阶段统计为 31/14/8，总计 53。
2. 公文交换全部标记为 deferred，不分配 S1～S5 工作包。
3. 一期、二期、三期统计使用“阶段”字段，未误用 P0/P1/P2。
4. 所有需求映射到合法业务域或前端功能域。

## 证据

完成后在 `docs/execution/evidence/WP-006-requirement-baseline.md` 中记录核对结果和差异。
