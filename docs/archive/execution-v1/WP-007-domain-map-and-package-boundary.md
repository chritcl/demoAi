# WP-007：领域地图与业务包边界

## 目标

明确业务包职责、数据表 ownership、业务包依赖方向、跨包公开 Service 契约，为 G1 提供领域地图候选基线。

## 范围

- 明确 s0_xtsz～s8_audit 各业务包职责。
- 为每张表指定唯一 owner 业务包。
- 定义业务包依赖方向，禁止循环依赖。
- 登记跨包公开 Service 契约和跨域查询例外。
- 处理通讯录与系统设置之间的用户/组织数据边界。
- 确定信息发布、通知公告、公文管理是否属于同一业务包或需要拆分。

## 不在范围

- 不创建工程骨架。
- 不生成数据库迁移脚本。
- 不实现业务代码。
- 不最终批准业务包结构（G1 批准）。

## 依赖

- WP-006：需求基线与阶段映射（done）

## 风险

- 高：业务包边界与旧系统模块划分差异大，需要用户确认。
- 中：跨包数据查询例外控制不当会导致后续架构腐化。

## 验收标准

1. DOMAIN-MAP.md 中每张表有唯一 owner。
2. 不存在 s1_portal 或 s2_document 这类不确定 owner 表述。
3. 业务包依赖方向无循环。
4. 跨包调用契约已登记，状态明确。
5. 文档明确标注“需 G1 批准”。
