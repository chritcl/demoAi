# 路线图（ROADMAP）

本文件定义 demoAi 项目从 S0 到 S6 的演进路线图。

当前阶段、活动门禁和工作包状态以 `docs/execution/STATE.json` 为唯一真源；本文件只描述各阶段目标，不记录当前状态。

## 阶段目标

### S0：仓库治理与执行底座

1. 完成仓库审计与凭据风险处理（WP-000）。
2. 重建文档真源（WP-001）。
3. 建立 Codex 执行协议（WP-002）。
4. 定义架构边界与 ADR 待办（WP-003）。
5. 建立执行体系自动验证（WP-004）。
6. 修复 G0 后执行体系一致性（WP-005）。
7. 通过 G0 门禁。

### S1：需求与架构基线

1. 评审并批准 S1 所需的 ADR。
2. 冻结技术版本基线。
3. 决定流程引擎选型。
4. 完成需求基线与阶段映射（WP-006）。
5. 完成领域地图与业务包边界（WP-007）。
6. 完成核心技术与架构 ADR（WP-008）。
7. 完成 API、安全与非功能基线（WP-009）。
8. 汇总 G1 门禁材料（WP-010）。
9. 通过 G1 人工门禁。

> 注：S1 禁止创建后端业务工程、PC 工程、uni-app 工程、数据库迁移脚本或业务代码。

### S2：工程骨架

1. 后端可构建、可运行基础 API。
2. PC 端可构建、可运行基础页面。
3. 移动端（uni-app）可构建、可运行基础页面。
4. 数据库迁移基线可执行。
5. CI 通过基础构建和架构测试。
6. 通过 G2 自动门禁。

### S3：第一条端到端纵向切片

1. 实现一个完整业务闭环（例如通知公告、请休假或信息发布）。
2. 贯通数据库、后端业务包、API、PC、uni-app H5、权限、审计、自动化测试。
3. 通过 G3 人工门禁。

### S4：一期能力

1. 实现一期全部需求（以 WP-006 冻结后的基线为准）。
2. 通过一期业务测试。
3. 通过 G4 自动门禁。

### S5：二期能力

1. 实现二期业务扩展。
2. 回归测试通过。
3. 通过 G5 自动门禁。

### S6：发布准备

1. 系统验收。
2. 部署文档完整。
3. 用户签署交付。
4. 通过 G6 人工门禁。

## 三期能力

- 三期需求已在 `docs/product/GOAL.md` 和 `docs/product/SCOPE.md` 中保留映射，并在 `docs/product/TRACEABILITY.md` 中标记为 `deferred`。
- 三期能力不得进入 S1～S5 实施工作包。
- 三期将在 S6 后另行规划。

## 路线图维护

- 本文件由每个阶段首个工作包负责维护。
- 阶段升级后，不硬编码当前阶段，所有动态状态以 `STATE.json` 为准。
- 路线图变更必须经过对应阶段人工门禁批准。
