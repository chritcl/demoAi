# 阶段与门禁（STAGE-GATES）

本文件定义 demoAi 项目从 S0 到 S6 的阶段划分和每个阶段结束时的门禁条件。

## 阶段总览

| 阶段 | 名称 | 目标 | 门禁 |
|---|---|---|---|
| S0 | 仓库治理与执行底座 | 建立执行体系、文档真源、架构边界 | G0 |
| S1 | 架构决策与工程约定 | 冻结技术版本、架构决策、工程骨架 | G1 |
| S2 | 工程骨架与验证 | 建立可运行、可测试的后端/前端/移动端骨架 | G2 |
| S3 | 一期业务核心 | 实现一期核心业务 | G3 |
| S4 | 一期业务完善 | 完善一期业务、集成测试 | G4 |
| S5 | 二期业务扩展 | 实现二期业务 | G5 |
| S6 | 系统收尾与交付 | 验收、文档、部署 | G6 |

## 各阶段工作包

### S0 工作包

- WP-000：仓库审计与凭据风险处理
- WP-001：文档真源重建
- WP-002：Codex 执行协议
- WP-003：架构边界与 ADR 待办
- WP-004：执行体系自动验证

### S1 工作包（待规划）

- 技术版本 ADR 评审
- 流程引擎 ADR 评审
- 工程骨架创建
- 架构测试引入

### S2 及以后工作包

S2 至 S6 的工作包在 S1 门禁通过后由后续规划定义。

## 门禁定义

### G0：S0 结束门禁

- 类型：`hybrid`（自动条件 + 人工确认）
- 自动条件：
  - WP-000 至 WP-004 均为 `done`。
  - `node tools/execution/validate.mjs` 通过。
  - 工作区干净。
- 人工条件：
  - 用户确认 `old/` 之外没有新的真实凭据。
  - 用户确认当前文档真源和架构边界可接受。
- 通过后状态：`waiting_human`。

### G1：S1 结束门禁

- 类型：`human`
- 条件：
  - ADR-001 至 ADR-010 中所有 S1 相关 ADR 被批准为 `accepted`。
  - 工程骨架可运行、可构建、可通过架构测试。
  - 流程引擎选型已决定。
  - 技术版本已冻结。
- 通过后状态：进入 S2。

### G2：S2 结束门禁

- 类型：`automatic`
- 条件：
  - 后端、PC 端、移动端骨架可构建。
  - CI 通过。
  - 架构测试通过。
- 通过后状态：进入 S3。

### G3：S3 结束门禁

- 类型：`human`
- 条件：
  - 一期核心业务完成并通过测试。
  - 用户验收通过。
- 通过后状态：进入 S4。

### G4：S4 结束门禁

- 类型：`automatic`
- 条件：
  - 一期业务完善完成。
  - 集成测试通过。
  - 性能基准可接受。
- 通过后状态：进入 S5。

### G5：S5 结束门禁

- 类型：`automatic`
- 条件：
  - 二期业务扩展完成。
  - 回归测试通过。
- 通过后状态：进入 S6。

### G6：S6 结束门禁

- 类型：`human`
- 条件：
  - 系统验收通过。
  - 部署文档完整。
  - 用户签署交付。
- 通过后状态：项目完成。

## 门禁状态机

每个门禁具有以下状态：

- `pending`：未开始评估。
- `in_review`：正在评估条件。
- `automatic_passed`：自动条件通过，等待人工确认（仅 hybrid 门禁）。
- `waiting_human`：到达人工条件，等待用户批准。
- `approved`：已批准，可进入下一阶段。
- `rejected`：未通过，需修复后重新评估。

## 自动连续执行

- `STATE.json` 中的 `auto_continue_until_gate` 为 `true` 时，Codex 可自动连续执行处于 `ready` 的工作包，直到遇到人工门禁或强制停止条件。
- 当遇到 `waiting_human` 状态时，必须停止并等待用户明确批准。

## 阶段升级流程

1. 本阶段所有工作包完成并提交。
2. 运行阶段验证命令。
3. 评估门禁条件。
4. 如果是自动门禁，通过则进入下一阶段。
5. 如果是人工门禁，状态设为 `waiting_human` 并等待用户批准。
6. 用户批准后，更新 `STATE.json` 中的 `active_stage` 和 `active_gate`。

## 与执行协议的关系

`EXECUTION-PROTOCOL.md` 定义工作包执行流程；`STAGE-GATES.md` 定义阶段和门禁条件。两者共同构成完整的执行控制体系。
