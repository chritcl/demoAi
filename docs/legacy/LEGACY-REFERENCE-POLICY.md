# 遗留代码参考策略

## 范围

本策略适用于 `old/` 目录以及 `docs/legacy/` 下的所有遗留参考材料。

## 允许

- 查看字段含义。
- 查看字典值。
- 查看历史业务流程。
- 查看页面交互。
- 查看表之间的业务关系。
- 查看用户角色和权限需求。
- 提取需要重新验证的业务规则。

## 禁止

- 新代码引用 `old/`。
- 复制整个旧类、旧页面或旧 SQL。
- 沿用旧包结构作为新架构。
- 直接沿用旧数据库主键和状态码。
- 沿用旧真实地址、账号、密码和密钥。
- 把旧代码能运行作为新工作包完成证据。
- 修改旧代码来实现新功能。

## 治理修改

`old/` 原则上只读，仅允许以下三类治理修改：

1. 新增或更新 `old/README.md`，声明遗留参考边界。
2. 对已跟踪文本文件执行凭据脱敏。
3. 删除已经提交的 `target/`、`dist/`、`node_modules/`、`*.class`、`*.jar` 等生成产物。

除此之外，不得修改旧业务逻辑、旧 SQL 结构、旧页面行为或旧接口实现。

## 凭据处理

- 旧文件中的数据库密码、Redis 密码、JWT 密钥、默认管理员密码和旧服务地址已替换为环境变量占位符或明显无效值。
- Git 历史仍可能保留原始凭据；是否重写 Git 历史需要用户人工决定。
- 使用旧配置前必须确认对应环境已撤销或轮换。
