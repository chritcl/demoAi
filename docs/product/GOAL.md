# 总目标

## 目标陈述

在不复用旧实现、不迁移旧数据的前提下，依据已确认的一期和二期需求，重建一个可部署、可测试、可审计、可持续演进的协同办公平台。

## 成功标准

1. 后端为单 Maven、单 Spring Boot、业务包分层单体，可独立构建、测试、部署。
2. PC 端为 Vue3 + TypeScript，可通过自动化测试验证主要业务闭环。
3. 移动端为 uni-app + Vue3，一期交付 H5 端。
4. 数据库结构重新设计，使用版本化迁移（Flyway 或 ADR 批准的等价方案）。
5. 统一身份、权限、组织、流程、文件、消息和审计能力。
6. 所有阶段通过自动化质量门禁验证。
7. 每个业务功能都有需求编号、工作包、验收标准和测试证据。

## 当前范围

- 一期需求：31 项功能，以门户、信息发布、通知公告、公文管理、综合办公、通讯录、工作台、应用支撑平台为主。
- 二期需求：13 项功能，扩展资产、办公用品、公文交换等。
- 必要的平台基础能力：身份认证、权限、组织、流程、文件、消息、审计。
- PC 端（Vue3 + TypeScript）。
- uni-app H5 基础交付。
- 后端业务包分层单体。
- 全新数据库结构。

## 不在当前范围

- 三期公文交换完整建设。
- Android/iOS/鸿蒙正式发布。
- 禁止截屏、指纹、手势等原生深度能力。
- 真实第三方 SSO。
- 真实短信、电子签章、WPS 中台。
- 生产环境迁移。
- 旧数据迁移。
- 具体框架小版本（需经 ADR 冻结）。
- 流程引擎实现方式（需先完成 ADR 与验证）。

## 外部依赖

- 用户确认技术版本 ADR。
- 用户确认流程引擎选型 ADR。
- 用户确认凭据已轮换或环境已下线。
- 用户确认是否需要重写 Git 历史。

## 已知风险

- Git 历史保留旧凭据，需要用户决策是否重写。
- 旧需求文档与最终实现可能存在偏差，需要重新确认。
- 流程引擎选型直接影响架构设计，尚未决定。
- 跨业务包数据关系需要领域地图确认。

## 完成定义

S6 门禁 G6 通过，一期、二期功能全部完成并通过用户验收，具备发布条件。
