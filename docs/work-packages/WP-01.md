# WP-01 工程骨架与开发环境

## 目标

建立后端、PC、uni-app 三个工程骨架，建立独立的前端依赖与构建环境、数据库迁移基础和本地架构验证能力。

## 范围

1. 后端工程骨架：Maven 单工程、Spring Boot 基础配置、既定业务包及 controller、service、service.impl、mapper、entity、dto、vo 分层约束、Result<T> 统一返回、BusinessException 全局异常处理和 ArchUnit 包边界测试。
2. PC 工程骨架：Vue3、TypeScript、Element Plus、路由、状态管理、请求封装和基础布局。
3. uni-app 工程骨架：uni-app、Vue3、H5 构建配置和基础页面。
4. 前端工程独立依赖管理：PC 与 mobile 分别维护 package.json 和 pnpm-lock.yaml；根目录不建立 pnpm workspace；两个工程可独立安装、构建和部署。
5. 数据库迁移：Flyway 或等价方案及基础表结构脚本。
6. 仅建立实际需要的目录、包结构和架构约束；业务包中的 Controller、Service、Mapper、Entity、DTO、VO 及业务页面在对应纵向工作包按实际需要创建，不以空实现冒充工程骨架完成。

## 依赖

无。

## 不在范围

- 业务功能实现。
- 旧代码迁移。
- 生产环境配置。
- 大量空类、空 Controller、空 Service 或占位页面。
- GitHub Actions、远程 CI 或其他远程流水线。

## 验收标准

1. 后端测试和构建通过。
2. PC 测试和构建通过。
3. uni-app H5 构建通过。
4. 数据库迁移验证通过。
5. ArchUnit 架构验证通过。

## 本地验证命令

```bash
# 后端测试与构建
cd backend && mvn --batch-mode clean verify

# 数据库迁移验证
cd backend && mvn --batch-mode -Dtest=SchemaMigrationTest test

# ArchUnit 架构验证
cd backend && mvn --batch-mode -Dtest=ArchitectureRulesTest,ArchitectureViolationFixtureTest test

# PC 测试与构建
cd pc && pnpm install --frozen-lockfile && pnpm test && pnpm build

# uni-app H5 构建
cd mobile && pnpm install --frozen-lockfile && pnpm build:h5
```
