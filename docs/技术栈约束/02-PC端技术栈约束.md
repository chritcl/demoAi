# PC 端技术栈约束（oa-frontend）

> 适用模块：`oa-frontend/`（Vue3 + Vite + Element Plus，端口 10002）
> 本文件是 PC 端开发的强制约束，新增/升级依赖、变更架构须先评审。

## 一、技术栈锁定（版本基线）

| 分类 | 技术 | 版本 | 说明 |
|---|---|---|---|
| 框架 | Vue | **3.4.x**（Composition API） | `<script setup>` |
| 构建 | Vite | **5.2.x** | 不用 webpack/vue-cli |
| 语言 | JavaScript（ES2020+） | — | 可选 TypeScript（需团队共识） |
| UI 库 | Element Plus | 2.7.x | 按需/全量统一，项目内不混用其他 UI 库 |
| 图标 | @element-plus/icons-vue | 2.3.x | |
| 路由 | Vue Router | 4.3.x | 动态路由由后端 `/auth/routers` 下发 |
| 状态 | Pinia | 2.1.x | 替代 Vuex |
| HTTP | Axios | 1.7.x | 统一封装 `request.js` |
| 进度条 | NProgress | 0.2.x | |
| Cookie | js-cookie | 3.0.x | token 存取 |
| 样式 | Sass | 1.77.x | |

> 所有依赖版本锁在 `package.json` + `pnpm-lock.yaml`（包管理统一 pnpm），禁止使用 `^`/`~` 导致隐式升级（生产锁定具体版本）。

## 二、目录结构约束

```
oa-frontend/
├── public/
├── src/
│   ├── api/          接口请求（按模块拆分：system/、office/、document/…）
│   ├── assets/       静态资源（图片/字体/全局样式）
│   ├── components/   全局复用组件
│   ├── layout/       布局（侧边栏/导航/标签页/面包屑）
│   ├── router/       路由（静态 + 动态路由生成）
│   ├── store/        Pinia（user/permission/tagsView…）
│   ├── utils/        工具（request/auth/permission/directive…）
│   ├── views/        页面（按业务模块分目录）
│   ├── App.vue
│   └── main.js
├── vite.config.js
└── package.json
```

> 页面目录与后端模块对齐：`views/system`、`views/portal`、`views/document`、`views/office`、`views/contacts`、`views/workflow`、`views/workbench`。

## 三、编码规范

### 3.1 组件

- 一律 `<script setup>` 写法，不混用 Options API。
- 组件名大驼峰（`UserSelect.vue`），文件名与组件名一致。
- props 用 `defineProps`，事件用 `defineEmits`，类型/默认值显式声明。

### 3.2 请求

- 统一用 `@/utils/request` 的 axios 实例，**禁止**每个页面自行 `new axios`。
- 请求基础地址 `/`，开发环境 Vite 代理到 `http://localhost:10001`（见 `vite.config.js`）。
- 携带 token：请求拦截器从 cookie 读 token 加到 `Authorization: Bearer xxx`。
- 响应拦截器：`code !== 200` 统一 `ElMessage.error(msg)`；401 跳登录。

### 3.3 状态管理

- 用户态（token/用户信息/角色/权限）放 `useUserStore`；权限放 `usePermissionStore`。
- 组件局部状态用 `ref/reactive`，跨组件共享才进 Pinia。

### 3.4 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 组件/页面 | 大驼峰 | `OfficeLeave.vue` |
| 变量/方法 | 小驼峰 | `fetchList` |
| 常量 | 全大写下划线 | `PAGE_SIZE` |
| CSS class | 蛇形/kebab | `.leave-form` |
| 路由 path | 蛇形小写 | `/office/leave` |
| API 方法 | 动词+名词 | `getLeaveList`、`submitLeave` |

## 四、权限约束（红线）

1. **动态路由**：登录后调 `/auth/routers` 获取菜单，`addRoute` 注入；前端**不得**写死路由表。
2. **按钮级权限**：用指令 `v-hasPerm="'office:leave:submit'"` 或方法 `user.hasPerm()` 控制按钮显隐。
3. **菜单/数据**：以后端下发为准，前端不做权限判断兜底（后端是最终防线）。
4. **token**：存 cookie（可设 httpOnly 由后端写），前端不存 localStorage 明文敏感信息。

## 五、样式与 UI

- 全局主题色/间距走 Sass 变量，不硬编码颜色值。
- Element Plus 组件统一中文化（`locale` zh-cn）。
- 列表页统一布局：搜索表单 + 操作按钮 + 表格 + 分页（封装 `<ProTable>` 复用）。
- 表单校验用 `el-form` rules，提交前 `formRef.validate()`。
- 响应式：以 PC 桌面为主，最小兼容 1280px；移动端体验由 `oa-mobile` 承担。

## 六、性能

- 路由懒加载：`() => import('@/views/...')`，禁止全量打包到首屏。
- 大表格用虚拟滚动或分页，禁止一次性渲染千行。
- 图片走后端 `/file/{id}`，缩略图由后端裁剪。
- 生产构建：`pnpm run build` → `dist/`，禁用 sourcemap 上线。

## 七、与后端接口契约

- 统一响应 `{code, msg, data}`；分页 `{rows, total}` 或 `PageResult`。
- 时间：统一时间戳或 `yyyy-MM-dd HH:mm:ss` 字符串（以后端为准）。
- 字典：下拉选项统一从 `/system/dict/data/type/{type}` 获取，不写死。
- 文件：上传 `/file/upload`，预览 `/file/{id}`（图片可直接 src）。

## 八、禁止项（红线清单）

- ❌ 换框架（React/jQuery）或混用其他 UI 库（Ant Design/Naive 等）
- ❌ 前端写死路由/权限（绕过后端动态下发）
- ❌ 每个页面自建 axios / 自定义 baseURL
- ❌ 明文存敏感信息到 localStorage
- ❌ 引入未在 package.json 声明的依赖
- ❌ 上线带 console.log / sourcemap
- ❌ 在 PC 端实现移动端专属 UI（应由 oa-mobile 承担）
