# 移动端技术栈约束（oa-mobile）

> 适用模块：`oa-mobile/`（uni-app + Vue3，一套代码编译 H5 / Android App / iOS App / 鸿蒙）
> 本文件是移动端开发的强制约束，新增/升级依赖、变更架构须先评审。
> 技术路线说明：替代原“Vant H5 + 原生 WebView 封装”方案。功能清单中移动端包含基础能力（H5）与 Android/iOS/鸿蒙客户端，uni-app 一次开发多端编译，原生能力（扫码/定位/推送/指纹/禁止截屏/版本更新）由 `uni.*` API 与条件编译覆盖，符合 uniapp 开发需求。

## 一、技术栈锁定（版本基线）

| 分类 | 技术 | 版本 | 说明 |
|---|---|---|---|
| 框架 | uni-app | Vue3 版（DCloud 官方 Vite 模板） | 一次开发，多端编译 |
| 语法 | Vue | **3.4.x**（Composition API） | `<script setup>` |
| 构建 | Vite | 5.x（uni-app 内置） | |
| UI 库 | wot-design-uni | 1.x | uni-app 专用 Vue3 组件库，**禁止**混用 Element Plus / Vant |
| 路由 | uni-app 页面路由 | `pages.json` | **禁止**使用 vue-router |
| 状态 | Pinia | 2.1.x | |
| HTTP | `uni.request` 自封装 | `utils/request.js` | 保持与 PC 端一致的 code/401 约定 |
| 包管理 | pnpm | — | 依赖锁在 `package.json` + `pnpm-lock.yaml` |
| 开发工具 | HBuilderX | 4.x | App 真机调试 / 云打包；H5 端可纯 Vite 开发 |

## 二、多端编译与端矩阵

| 目标端 | 构建命令 | 对应清单功能 | 说明 |
|---|---|---|---|
| 移动 H5 | `pnpm run build:h5` | 移动端基础能力（一期） | 浏览器 / 企业微信 / 钉钉内嵌 |
| Android App | `pnpm run build:app-android` | Android 客户端（7.0+，三期） | APK/AAB，云打包 |
| iOS App | `pnpm run build:app-ios` | iOS 手机客户端（12.0+，三期） | 云打包 |
| 鸿蒙 | uni-app 鸿蒙适配版编译 | 鸿蒙原生客户端（三期） | 备选：ArkTS 原生壳直接内嵌 H5 产物，不再自研 bridge |

- 端差异统一用条件编译处理：`#ifdef APP-PLUS / H5 / MP-WEIXIN`，业务代码不直接判断 UA。
- 一期、二期以 H5 端为交付范围；App/鸿蒙列保留清单映射，架构上不新增代码分支。

## 三、目录结构约束

```
oa-mobile/
├── src/
│   ├── api/          接口请求（按模块，与 PC 端同构）
│   ├── components/   复用组件（审批操作栏/空状态/卡片…）
│   ├── pages/        页面（home/message/notice/approve/contacts/mine…）
│   ├── static/       静态资源（随包发布）
│   ├── store/        Pinia（user/…）
│   ├── utils/        工具（request/auth/platform…）
│   ├── App.vue
│   ├── main.js
│   ├── pages.json    页面路由 + 窗口样式 + 原生 tabBar
│   └── manifest.json 应用标识、各端权限与打包配置
├── package.json
└── pnpm-lock.yaml
```

> 移动端页面聚焦：消息提醒、新闻公告、流程审批与发起、文件查询、通讯录、个人设置。

## 四、编码规范

### 4.1 组件

- `<script setup>` 写法，组件名大驼峰。
- uni 内置组件（`view`/`scroll-view`/`swiper`…）+ wot-design-uni 组件直接使用。

### 4.2 请求

- 统一 `@/utils/request`，基于 `uni.request` 封装；**禁止**每个页面自行发请求。
- token 从 `uni.getStorageSync` 读取，请求头加 `Authorization: Bearer xxx`。
- 响应处理：`code !== 200` 统一 `uni.showToast`；401 `uni.reLaunch` 到登录页。
- 开发环境 Vite 代理到 `http://localhost:10001`，baseURL 按环境变量区分。

### 4.3 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 组件/页面 | 大驼峰 | `ApproveDetail.vue` |
| 变量/方法 | 小驼峰 | `loadTodo` |
| pages.json path | 蛇形小写 | `pages/approve/detail` |
| API 方法 | 动词+名词 | `getTodoList`、`approveTask` |

## 五、原生能力接入（替代 native-bridge）

不再自研 `native-bridge.js` / `window.OABridge`。原生能力统一走 uni API + 条件编译：

| 能力 | 方案 |
|---|---|
| 扫码 | `uni.scanCode` |
| 定位/考勤打卡 | `uni.getLocation`（manifest 配置 App 权限） |
| 消息推送 | uni-push 2.0；H5 端降级 WebSocket/轮询 |
| 指纹/面容 | `uni.startSoterAuthentication`，策略存 `sys_user_security` |
| 手势密码 | 自绘手势页（App 端条件编译），校验记录同上 |
| 禁止截屏 | App-Android 用 `plus.android` 设置 `FLAG_SECURE`（条件编译/uts 插件）；H5 端能力受限，仅策略上报 |
| 水印 | 页面级 Canvas/样式渲染，策略由 `sys_security_policy` 下发 |
| 版本更新 | App 热更新（wgt）+ 整包升级，灰度与断点续传由 `sys_app_version` 控制 |

## 六、UI / 交互

- 设计基准 750rpx，用 uni-app `rpx` 自适应，**禁止** rem/vw 方案混用。
- 底部 Tab 用 `pages.json` 原生 tabBar，不自绘。
- 列表用页面级 `onPullDownRefresh` 下拉刷新 + `onReachBottom` 上拉加载，禁止一次性渲染长列表。
- 审批页统一底部操作栏组件（通过/驳回/转办 + 意见输入）。
- 全局 loading：`uni.showLoading`；轻提示：`uni.showToast`。
- 安全区适配：底部 Tab/操作栏预留 `safe-area-inset-bottom`。

## 七、性能与打包

- 页面按需注册，非首页功能走分包（`pages.json subPackages`），主包 ≤ 2M。
- 图片用 `lazy-load`；附件走后端 `/file/{id}`。
- 接口并发拉取首屏数据（Promise.all）；首页卡片数据缓存（Pinia + uni storage）。
- 生产构建：`pnpm run build:h5` → `dist/build/h5`，禁 sourcemap；App 用 HBuilderX 云打包。
- 上线禁 `console.log`。

## 八、安全约束

1. **token 安全**：不明文存 H5 localStorage；App 端用 uni 存储沙箱，登录态与 PC 端同一套后端签发。
2. **水印**：前端渲染 + 策略表控制（`policy_key=water_mark`）。
3. **禁止截屏**：以 App 端原生能力为准，H5 仅配合策略上报。
4. **手势/指纹**：APP 启动验证由 App 端 + `sys_user_security` 完成。

## 九、与后端接口契约

- 与 PC 端复用同一套后端 API（`/auth/*`、`/workflow/*`、`/office/*`、`/document/*`、`/file/*`）。
- 待办/已办：`/workflow/task/todo`、`/workflow/task/done`。
- 流程发起/审批：`/workflow/start`、`/workflow/approve`、`/workflow/reject`、`/workflow/transfer`。
- 字典、文件、通讯录接口与 PC 端一致。

## 十、禁止项（红线清单）

- ❌ 混用 Element Plus / Vant 等仅支持 H5 的 UI 库（App 端无法渲染）
- ❌ 使用 vue-router（uni-app 路由由 `pages.json` 管理）
- ❌ 直接操作 DOM/BOM（`document`/`window`），App 端不存在；浏览器 API 一律条件编译隔离
- ❌ 自研 native-bridge 或直接调用未约定的原生插件
- ❌ 每个页面自建请求 / 自定义 baseURL
- ❌ 明文存敏感信息到 localStorage
- ❌ 使用 npm / yarn（统一 pnpm）；引入未在 package.json 声明的依赖
- ❌ 上线带 console.log / sourcemap
- ❌ 在移动端实现 PC 桌面专属复杂表格/管理后台 UI（由 oa-frontend 承担）
